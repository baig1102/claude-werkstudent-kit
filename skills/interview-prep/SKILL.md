# interview-prep

One interview, one brief, one drill. It teaches the idea, not a script.

## 0. Before you start
1. Confirm today's date and the interview date, time, format (phone, video, on site), language and participants.
2. Read the tracker row (`jobs`), its `interview_notes`, the contact (`contacts`) and open prep tasks.
3. Read the project instructions (truth rules, timetable, hours), `language-level.md`, and the CV variant used for this application.
4. Open the posting again and the company's own website (products, location, team). Say what you used; mark anything not found as unknown.

## 1. Anchor stories (first session only, then reuse)
Ask the user for 3–5 real stories from work, studies or projects. For each: what happened → what was hard → what the user did → what came out of it. Check each against the CV. Save them in the project (file `anchor-stories.md`) so later sessions reuse them. Never add details the user did not give.

## 2. Brief (one screen)
- The role in 3 lines; the 3 tasks that matter most; who interviews and what they care about.
- Fit map: each top task → the anchor story that proves it.
- Real gaps for this role, with one honest sentence each and how the user is closing the gap. Never hide a gap; never volunteer gaps as a list.
- Consistency: what the user already told this company or its recruiter (from `interview_notes`). New answers must match.
- Logistics: commute, days on site, weekly hours (within the limit, all jobs together), free days, start date, pay range from the posting, contract type and length to ask about, other running processes and their dates.
- 5 questions for them (a typical week, tools, onboarding, on-site days, next step and decision date).

## 3. Question set (10–12)
Opening and self-introduction (60–90 seconds); why this company and role; 3–4 task questions taken from the posting; one question about a mistake or conflict; availability and commute; salary; language level; plans after the degree. Second round: add one practical case from the role.

## 4. Drill
- One question at a time, in short simple sentences in the interview language (about 15 words at most). If that language is not English and the user's level is below B2, put the English underneath.
- Wait for the answer. The user may answer by voice; transcription errors are not the user's errors. The user may switch to English when stuck; then help to say it simply in the interview language.
- Feedback after each answer, four short parts: what was good (1–2 points) · what can be better (1–2) · language (2–3 corrections, at most 5 new words, for German with article and plural) · idea outline (3–4 key points; no full model answer unless asked).
- Then one realistic follow-up question that tests whether the story is real.
- If an answer sounds memorised or generic, say so. Rule of thumb: 2–3 short sentences, then stop.
- Phone screens: practise the first 30 seconds, asking for a name again, asking the speaker to repeat, and repeating the question in the user's own words.
- After a full mock: the 3 strongest points, the 3 weakest, which questions to repeat, and 3 surprise follow-ups.

## 5. After the real interview
Ask what was asked, what went well, and what they said about next steps, pay, start date and on-site days. Write it into `interview_notes`, add a thank-you task for the same day and a follow-up task under the job-followup rules. Draft the thank-you (3–5 sentences, one concrete point). The user sends it.

## Truth rules
Only facts the user stated or that are in the CVs and certificates; never combine separate facts. Stay inside the "Real scope" lines. Language level exactly as certified. Respect the confidentiality line. Never coach an answer that is not true, even if it would sound better. Do not bring up earlier rejections by the same company unless asked; then answer briefly and honestly.

## Guardrails
No messages, emails or calendar entries are sent. Tracker writes only: `interview_notes`, prep task done, new thank-you and follow-up tasks.

## Failure modes
Interview details unknown → say what is missing and draft a one-line question the user can send to the recruiter. Posting gone → use the tracker `fit` text and say the posting could not be re-read. Less than 30 minutes left → brief, self-introduction, and the 3 most likely questions only.
